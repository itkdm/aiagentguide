# 入门学习路线

这一篇负责把前面的认知内容收束起来，明确告诉读者：看完入门以后，应该去哪一栏，分别带着什么问题继续看。

和前面几篇不同，这一篇不再继续解释概念，而是把整栏内容收口，帮助你决定下一步应该进入 [原理](../principles/index.md)、[RAG](../rag/index.md)、[项目](../projects/index.md) 还是 [工具](../tools/index.md)。

## 读完这一篇，你应该能回答什么

- 看完入门后，接下来最合适的学习方向是什么
- 不同目标和背景的人，应该优先看哪一栏
- 怎样避免"看了很多内容，但顺序是乱的"这种低效学习方式

1. 先理解 Agent 是什么
2. 再分清 Agent、聊天机器人、工作流和 RAG
3. 再判断什么任务值得用 Agent
4. 再看 Agent 是怎么运转的
5. 再理解核心组件和常见误区
6. 最后进入原理、RAG 和项目实践

如果你是第一次系统接触 AI Agent，建议不要跳着看。前几篇内容之间其实是有依赖关系的：

- 不知道 Agent 是什么，就容易把产品宣传语当成事实
- 不会判断任务结构，就容易一上来就问"该学哪个工具"
- 不理解运行机制和核心组件，后面做项目时很难定位问题

所以这一栏真正想建立的，不是"记住多少名词"，而是一套稳定的学习顺序。

## 先把这一栏学到什么程度，才算够

你不需要把每个概念都背到非常细，但至少应该能回答下面这些问题：

- 什么是 Agent，它和聊天机器人有什么区别
- 哪些任务适合 Agent，哪些任务更适合工作流
- 一个 Agent 至少包含哪些关键组件
- 为什么 Agent 系统通常是循环执行，而不是一次生成
- 第一个 Agent 应该如何控制范围和风险

如果这几个问题都已经大体清楚，就可以进入下一阶段。

## 如果你想先理解系统怎么运转

接下来进入 [原理](../principles/index.md)，重点带着这些问题去看：

- Agent 的执行循环是怎么设计的
- 上下文、记忆和工具调用各自解决什么问题
- 多 Agent 协作的边界和通信方式是什么
- 可靠性、权限和观测在系统里放在什么位置

这一阶段不要急着找工具，而要先把"系统为什么这样设计"看清楚。

## 如果你主要关心知识库问答

接下来进入 [RAG](../rag/index.md)，重点带着这些问题去看：

- 你的场景到底需要检索增强，还是需要完整 Agent
- 检索、重排和上下文拼装各自影响什么
- 知识库的构建、更新和评测怎么做
- 生产化部署时哪些环节最容易出问题

很多知识库项目真正需要的是"检索 + 生成"，而不是复杂 Agent。先把这个边界看清楚，能帮你少绕很多弯路。

## 如果你想看真实项目怎么做

接下来进入 [项目](../projects/index.md)，重点带着这些问题去看：

- 这个项目的目标、边界和成功标准是什么
- 它用了哪些能力，为什么是这些能力
- 它在哪些地方做了控制，失败时如何修正
- 它的架构权衡和可复制经验是什么

项目栏更适合你已经建立基础判断之后再看。否则很容易出现下面这种情况：

- 案例看了很多
- 名字记了很多
- 但还是不知道自己到底应该从哪里开始

所以项目页更像"参照系"，不是"起点"。

## 如果你主要关心工具产品

接下来进入 [工具](../tools/index.md)，重点带着这些问题去看：

- 这是产品、框架，还是平台
- 它更适合个人效率、团队流程还是开发者搭建
- 它强调的是交付体验，还是工程可控性

工具栏更适合你已经建立基础判断之后再看。否则很容易出现下面这种情况：

- 产品看了很多
- 名字记了很多
- 但还是不知道自己到底应该从哪里开始

所以工具页更像"地图"，不是"起点"。

## 按目标选择下一步

### 想做办公自动化或内容处理

- 先看工具产品和低代码平台
- 再看项目案例

这类方向通常更适合先强调结果和交付速度，再逐步补工程控制。

### 想做浏览器操作型 Agent

- 先理解工具调用和执行循环
- 再重点看相关工具与项目

这类方向往往更容易碰到权限、登录态和执行稳定性问题，所以要比普通问答系统更早建立"控制点"的意识。

### 想做代码型 Agent

- 先理解状态、工具和执行控制
- 再进入原理和项目案例

代码型 Agent 往往对状态管理、文件读写、命令执行和错误恢复要求更高，更适合在理解系统结构后再深入。

### 想做知识库问答

- 先区分 RAG 和 Agent
- 不要一开始就默认自己需要完整 Agent 系统

很多知识库项目真正需要的是"检索 + 生成"，而不是复杂 Agent。先把这个边界看清楚，能帮你少绕很多弯路。

## 给不同背景读者的建议

### 如果你本来就会开发

你的优势是能更快理解工程结构，但也容易一上来就钻细节。建议先把任务判断看完，再进入原理和项目。

### 如果你更熟悉产品或运营

你的优势是更容易从任务目标和交付场景出发。建议先用平台化工具建立直觉，再逐步补系统结构。

### 如果你是内容创作者或知识工作者

不要急着学所有工具，可以先从"哪些任务值得交给 Agent"开始，优先建立任务判断力。

## 一个最实用的学习闭环

如果把整个入门阶段收缩成一个最短路线，可以按下面的顺序：

1. 先理解 Agent 与相邻概念的区别
2. 先判断你的任务是否真的需要 Agent
3. 先做一个最小闭环案例
4. 再进入原理和 RAG
5. 再去看更复杂的项目、工具和资源

这条路线看起来不激进，但它最符合长期学习效率。因为 AI Agent 这个领域变化很快，真正稳定的不是具体工具名字，而是你的判断方法。

## 看完入门栏后，建议去哪里

如果你现在更关心"系统怎么运转"，进入 [原理](../principles/index.md)。  
如果你现在更关心"知识库问答"，进入 [RAG](../rag/index.md)。  
如果你现在更关心"真实项目怎么做"，进入 [项目](../projects/index.md)。  
如果你现在更关心"现在有哪些东西"，进入 [工具](../tools/index.md)。

顺序上，仍然建议：

`入门 -> 原理 -> RAG / 项目 -> 工具 / 资源`

## 这一篇小结

- 入门不是为了把所有内容学完，而是为了知道下一步该去哪里
- 读完整个入门栏后，应该已经具备基础判断和最小路线感
- 真正高效的学习顺序是：判断先行，理解系统，再看项目与工具
